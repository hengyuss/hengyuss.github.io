C函数调用过程

函数调用过程几个重要的寄存器

  • epb 存储栈顶信息
  • esp 存储栈低信息
  • eip 存储下一条待执行指令的内存地址

caller:
    push $2
    push $1
    call callee
    add $8 %esp

callee:
    push %ebp
    mov %esp, %ebp
    sub $4, %esp
    mov $42, $eax
    mov %ebp, %esp
    pop $ebp
    ret

以上述代码为例子

flowchart LR subgraph caller_stack_frame ["function stack memory graph"] direction TB A[caller stack frame] B[ ] C[ ] D[ ] E[ ] end EBP((("EBP"))) --> A ESP((("ESP"))) --> A style caller_stack_frame #stroke:#333 style EBP stroke:#222 style ESP stroke:#222`
初始位置时esp和ebp指向同一地址,随后caller函数将立即数1,2压入栈中，esp作为栈低向下生长，此时eip指向call callee即即将开始调用callee

flowchart LR subgraph caller_stack_frame ["function stack memory graph"] direction TB A[caller stack frame] B[1] C[2] D[ ] E[ ] end EBP((("EBP"))) --> A ESP((("ESP"))) --> C style caller_stack_frame #stroke:#333 style EBP stroke:#222 style ESP stroke:#222`

随后进入调用callee的过程中,此时要为callee函数申请新的o栈,在此之前要保存之前eip将要执行的代码的地址，执行完call callee进入调用callee函数，那么返回后的地址就应该是add $8, %esp(参考上述caller中的汇编代码),这个地址也保存在栈中，即将add &8, %esp这段代码的地址压入栈中，方便从callee函数返回后，cpu知道从哪继续执行。

flowchart LR subgraph caller_stack_frame ["function stack memory graph"] direction TB A[caller stack frame] B[1] C[2] D[address of add $8, %esp] E[ ] end EBP((("EBP"))) --> A ESP((("ESP"))) --> D D --> address((("add $8, %esp"))) style caller_stack_frame #stroke:#333 style EBP stroke:#222 style ESP stroke:#222`

接下来要将原来的栈顶地址入栈，因为接下来的栈就是callee的栈了

flowchart LR subgraph caller_stack_frame ["function stack memory graph"] direction TB A[caller stack frame] B[1] C[2] D[address of add $8, %esp] E[address of caller stack frame ] end direction TB EBP((("EBP"))) --> ESP((("ESP"))) -->E D --> address1((("add $8, %esp"))) style caller_stack_frame #stroke:#333 style EBP stroke:#222 style ESP stroke:#222`

在执行callee的过程和caller类似，这里我们主要说执行callee后的返回过程.在callee中可以看到 pop %ebp，是将栈低 caller stack frame的地址也就是原来caller的栈顶地址弹入到ebp中，然后此时esp就指向了address of add %8, %esp

flowchart LR subgraph caller_stack_frame ["function stack memory graph"] direction TB A[caller stack frame] B[1] C[2] D[address of add $8, %esp] E[ ] end direction TB EBP((("EBP"))) --> A ESP((("ESP"))) --> D D --> address1((("add $8, %esp"))) style caller_stack_frame #stroke:#333 style EBP stroke:#222 style ESP stroke:#222`

在然后执行ret 汇编代码，将esp所指向的内存地址弹入到eip中也就是add $8, %esp这条命令,cpu 开始从这条命令执行，这条命令的意思就是将esp向上再升两个刚好跨过两个参数1,2的内存地址，epb=esp此时栈就被释放了。(为什么是add $8, %esl, 因为我们说的是32位的系统，每个内存地址是32位也就是4个字节，1,2两个参数分别占一个内存地址因此是两个内存地址也就是8个字节)

flowchart LR subgraph caller_stack_frame ["function stack memory graph"] direction TB A[ ] B[ ] C[ ] D[ ] E[ ] end direction TB EBP((("EBP"))) --> ESP((("ESP"))) --> D --> address1((("add $8, %esp"))) style caller_stack_frame #stroke:#333 style EBP stroke:#222 style ESP stroke:#222`

git submodule

如果在项目中引入了其他项目的仓库，如果要对这个仓库做一些更改，我们可以在本地进行修改，但如果要提交到远端仓库就没有办法了，我们可以将这个仓库fork到我们的仓库中去，然后修改父项目中的.gitmodule中该项目的url 例如

1
2
3

[submodule "themes/hugo-theme-stack"]
	path = themes/hugo-theme-stack
	url = https://github.com/hengyuss/hugo-theme-stack.git

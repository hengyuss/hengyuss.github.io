关于printf()函数的漏洞

void func(vodi){
    int secret = 42;
    printf("%d\n");
}

C中的printf函数的第一个参数格外重要，第一个参数是格式化字符串，如果在这个字符串中遇到%d,%s,这些格式化输入，printf就会在栈上找到第一个未使用的变量进行匹配，然后进行输出。

frame说明
RIP of func
SFP of func
secret = 42arg1
&"%d\n"arg0
RIP of printf
SFP of printf
printf frame

在这个栈帧中，printf函数就会找到arg1也就是secret = 42这个变量进行输出

off-by-one(一字节溢出)

通过这个溢出漏洞我们可以复习一下C函数的调用过程，仅仅是一个字节的溢出就让计算机处于危险的境地

void vulnerable(void){
    char name[20];
    fread(name, 21, 1, stdin);
}
int main(void){
    vulnerable();
    return 0;
}

在这个栈中name数组占20个字节，但是fread允许我们从输入21个字节进入栈当中，因为栈上分配的name数组只有20个字节，那么溢出的那一个字节就会被写进保存的上一个栈的EBP的值中，这样在该函数返回的时候EBP被指向到错误的内存地址，因为ESP的值是没有保存在栈中的，返回到上一个函数栈中的ESP的位置依赖于EBP，而EIP是通过ESP的位置从栈中弹出保存的从函数返回后继续执行的代码的地址，所以这样我们就可更改EIP的位置，进而执行一些恶意代码。让我们从图中看一看

但是从vulnerable函数返回后紧接着是main函数的返回处理，可以看到从vulnerable返回后，在main函数中开始执行 mov %ebp, %esp

这段name数组是我在vulnerable函数中申请的栈空间，我们在执行vulnerable函数的时候就可以对这些内存做一些更改,我们只用在输入的时候将0xbfffcd48这个地方的值改为恶意代码的地址。在随后的函数返回过程中，最终EIP就会指向这个地方，进而去执行恶意代码。

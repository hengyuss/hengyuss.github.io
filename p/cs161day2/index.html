关于C的一些安全问题

我对于C语言的应用仅限于做南大的PA1,而且很多C的API我也不是很熟悉，对于C的一些安全性问题的了解更是无从提起了。 今天学习的cs161的课程中提及了一些C中的安全性问题，其中主要的是C对于内存没有边界检查

C的栈溢出

C中有很多不安全的函数，这些不安全的函数大多数都和没有边界检查有关。有一个典型的例子是gets()函数。

因为C没有边界检查，用户通过gets()函数输入字符串，即使超过了name[20],C也不会组织用户的继续输出，所以用户就可以覆盖vulnerable这个函数的EIP的值，因为RIP of vulnerable就是从vulnerable返回之后，所执行的指令的地址，如果这个地址被覆盖成了一个恶意程序的地址，那么，计算机就会执行这个恶意程序，可能会被入侵，做各种危险的操作，比如如果在这里放入一段shellcode的代码地址，那么就会打开一个shell,入侵者可以通过这个shell执行各种命令。
那么shellcode如何放入内存中呢，同样可以利用gets()这个函数的漏洞，将shellcode汇编成机器语言后，通过gets()输入到栈中，在覆盖RIP of vulnerable的时候让其指向这个地址就行.

void func(int len, char *data){
    char buf[64];
    if (lenk > 64)
        return;
    memcpy(buf, data, len);
}

void *memcpy(void *dest, const void *src, size_t n);

这个函数的不安全在于func传入的是int类型的数字， 但是memcpy函数中size_t是一个无符号数
考虑这样一个例子，如果我调用func(-1, data)这个-1不会通过if(len > 64) 进而执行到memcpy这个函数，那么在memcpy这个函数中就会将-1解释为对应的无符号数也就是0xffffffff这是最大的无符号数了,这样就会造成程序的漏洞出现。
